Properly designing a computer network is a difficult task that requires planning, analysis, feasibility studies, and capacity planning.

Network designers use the Network Development Life Cycle (NDLC) to help with the process of designing a network.

The NDLC depends on previously completed development processes such as strategic business planning and applications development life cycle.

A top-down approach must be taken if an implemented network is to effectively deliver information systems fulfilling strategic business goals.

Application developers and networking specialists must work more closely together during the early stages of the application development process.

Two key components to any systems development effort are the process and the product of each stage of that development life cycle.

Effective network designs result from strict adherence to the top-down model by beginning with an analysis of business objectives.

The word cycle is a key descriptive term of the network development life cycle as it illustrates the continuous nature of network development.

A network designed from scratch clearly has to start with an analysis phase.

Physical network designs involve the arrangement and interconnection of the physical network circuits and devices.

Logical network designs involve configuration and definition of services that will run over the physical network.

Proposed network design changes are first simulated or prototyped before being deployed or implemented.

The monitoring of existing networks produces management and performance statistics which are analysed to fine tune the design.

Critical success factors of the NDLC include identification of all potential customers and political awareness.

Critical success factors also include buy-in, communication, detailed project documentation, and process/product awareness.

The overall network analysis and design process can be broken down into three major steps.

The first step is data traffic analysis, which examines all aspects of traffic passed between corporate locations.

The second step is circuit analysis and configuration alternatives, exploring possibilities for delivering data traffic reliably.

The third step is network hardware analysis and configuration alternatives, exploring data communications hardware devices.

The required outcome from the data traffic analysis process is a data traffic analysis report.

Flow analysis involves understanding the source and destination of each data conversation.

Payload type analysis considers video, voice, and data due to their bandwidth intensive transport demands.

Transaction analysis examines the source of data and calculates the amount of data required per transaction.

Time studies analyze when and how transactions are executed to influence bandwidth requirements.

Traffic volume analysis constructs a time sensitive traffic volume requirements profile.

Mission critical analysis considers requirements such as data security and redundant links.

Protocol stack analysis determines if the network will support more than one protocol.

All network requirements translate into four fundamental network design goals: scalability, availability, security, and manageability.

Scalable network designs can grow to include new user groups and remote sites without impacting existing users.

A network designed for availability delivers consistent, reliable performance 24 hours a day, 7 days a week.

Security is a feature that must be designed into the network, not added on after the network is complete.

A network that is too complex or difficult to maintain cannot function effectively and efficiently.

A hierarchical design is used to group devices into multiple networks organized in a layered approach.

The hierarchical design model has three basic layers: core layer, distribution layer, and access layer.

The core layer connects distribution layer devices.

The distribution layer interconnects the smaller local networks.

The access layer provides connectivity for network hosts and end devices.

Separating the various functions that exist on a network makes the network design modular.

The core layer is sometimes called the network backbone.

Routers and switches at the core layer provide high-speed connectivity.

The core layer provides optimal wide-area transport between geographically remote sites.

Services at the core layer are typically leased from a telecom service provider.

The core layer focuses on redundancy and reliability.

End stations should not be put in the core layer.

The distribution layer connects multiple networks within a campus network environment.

The distribution layer includes the campus backbone network based on FDDI, Fast Ethernet, Gigabit Ethernet, or ATM.

Network policy is often implemented in the distribution layer.

The access layer is usually a LAN or a group of LANs.

The access layer typically uses Ethernet, Token Ring, or FDDI.

The access layer can be divided into workgroup level and desktop level.

Remote dialup users are connected at the access layer tier.

The core layer provides optimal transport between core routers and distribution sites.

The distribution layer provides policy-based connectivity, peer reduction, and aggregation.

The access layer provides common group access to the internetworking environment.

Benefits of hierarchical network design include scalability, redundancy, performance, security, manageability, and maintainability.

Hierarchical networks scale very well because the modularity of the design allows you to replicate design elements.

Access layer switches are connected to two different distribution layer switches to ensure path redundancy.

The only layer where redundancy is limited is at the access layer.

Communication performance is enhanced by avoiding the transmission of data through low performing intermediary switches.

Properly designed hierarchical networks can achieve near wire speed between all devices.

Access layer switches can be configured with various port security options.

Manageability is relatively simple on a hierarchical network because each layer performs specific functions.

Consistency between switches at each layer allows for rapid recovery and simplified troubleshooting.

Hierarchical networks are easy to maintain because they are modular in nature and scale very easily.

Local carriers may be limited in their offering of certain data transmission services.

Capacity planning ensures sufficient bandwidth is allocated to handle sudden increase in demand.

The core layer is responsible for transporting large amounts of data quickly and reliably.

Implementing redundant links at the core layer ensures network devices can find alternate paths.

Most core layers in a network are wired in either a full-mesh or partial-mesh topology.

A full-mesh topology is one in which every device has a connection to every other device.

For larger installations, a modified partial-mesh topology is used.

Core routers and switches can contain dual power supplies and fans.

Technologies used at the core layer include routers or multilayer switches that combine routing and switching.

The distribution layer is associated with routing, filtering, and communication between the core and access layers.

The distribution layer is built using Layer 3 devices.

Distribution layer devices manage queues and prioritize traffic before transmission through the campus core.

Trunk links are often configured between access and distribution layer networking devices.

Trunks are used to carry traffic that belongs to multiple VLANs between devices over the same link.

Access control lists are a tool used at the distribution layer to limit access and prevent unwanted traffic.

An ACL is a list of conditions used to test network traffic that attempts to travel through a router interface.

ACLs can filter traffic based on source address, destination address, protocols, and port numbers.

There are three types of ACL: dynamic ACL, reflexive ACL, and time-based ACL.

Dynamic ACLs require a user to use telnet to connect to the router and authenticate.

Reflexive ACLs allow outbound traffic and then limit inbound traffic to only responses to those permitted requests.

Time-based ACLs permit and deny specified traffic based on the time of day or day of the week.

Route summarization is also called route aggregation or supernetting.

Route summarization creates smaller routing tables and less routing update traffic.

The access layer is used to control user access to the internetwork resources.

Many different devices can connect to an IP network including IP telephones and video cameras.

Redundant components and failover strategies can be implemented at the access layer to improve reliability.

Access layer management is crucial because of the increase in the number and types of devices connecting.

Designing for manageability includes considering naming structures, VLAN architecture, traffic patterns, and prioritization strategies.

A star-based WAN design connects all computers to one central computer that routes messages.

With backbone networks, the most important characteristic is the way in which packets are moved across the backbone.

There are three basic approaches used in backbone networks: routing, bridging, and switching.

Routed backbones move packets based on their network layer address.

The primary advantage of routed backbones is that they clearly segment each part of the network.

Disadvantages of routed backbones include time delays imposed by routers and high management requirements.

Bridged backbones move packets based on their data link layer address.

Advantages of bridged backbones include lower cost and simpler installation.

Disadvantages of bridged backbones include difficult individual segment management and slower network speed.

Most switched backbones use the data link layer address to move packets.

A collapsed backbone is the most common form of switched backbone.

Advantages of switched backbones include improved performance and far fewer networking devices.

The server responds with its X.509 digital certificate issued by a Certificate Authority.

The certificate includes the server's public key, domain name, validity period, and CA signature.

Certificate validation checks if the certificate is issued by a trusted CA, expired or revoked, and if the domain name matches.

S/MIME stands for Secure/Multipurpose Internet Mail Extensions.

S/MIME allows you to encrypt and sign email messages using public key cryptography.

S/MIME ensures email messages are confidential, authentic, and unmodified.

S/MIME is based on PKI which uses a public key and a private key.

The public key is used to encrypt or lock the message.

The private key is used to decrypt or unlock the message.

The public key can be shared with anyone but the private key must be kept secret.

S/MIME utilizes digital certificates that contain the public key and owner information.

Certificates are issued and verified by trusted third parties called certificate authorities.

Certificates help establish the trustworthiness and validity of public keys and identities.

GlobalSign is an example of a CA that issues and verifies digital certificates.

The digital certificate acts as a distinctive digital stamp indicating the content has remained unchanged.

Digitally signing an email with S/MIME creates a hash of the message.

The private key encrypts the hash to create the digital signature.

The digital signature and public key are attached to the message when sent.

The recipient validates the sender from the public key and verifies the hash matches the content.

If the hash does not match, it means the message has been altered.

Encrypting an email with S/MIME involves obtaining the recipient's public key.

The sender converts the message to ciphertext using a symmetric algorithm.

The symmetric algorithm is then encrypted using the recipient's public key.

The ciphertext and encrypted key are sent as a package file.

The recipient decrypts the ciphertext with their own private key using the same symmetric algorithm.

The decrypted message is called plaintext and is the original message.

A host can get an IP address by being hard-coded by a system administrator in a file.

DHCP stands for Dynamic Host Configuration Protocol.

DHCP allows a host to dynamically obtain its IP address from a network server when it joins the network.

DHCP allows a host to renew its lease on an address in use.

DHCP allows reuse of addresses since a host only holds an address while connected.

DHCP supports mobile users who want to join a network.

The DHCP overview begins with the host broadcasting a DHCP discover message.

The DHCP server responds with a DHCP offer message.

The host requests an IP address with a DHCP request message.

The DHCP server sends the address with a DHCP ack message.

The DHCP client creates an IP datagram containing its DHCP discover message.

The DHCP discover message uses a broadcast destination IP address of 255.255.255.255.

The DHCP discover message uses a source IP address of 0.0.0.0.

The DHCP client passes the IP datagram to the link layer which broadcasts the frame to all nodes on the subnet.

A DHCP server receiving a DHCP discover message responds with a DHCP offer message.

The DHCP offer message is broadcast to all nodes on the subnet using 255.255.255.255.

Several DHCP servers can be present on the subnet and the client may choose from several offers.

Each server offer message contains the transaction ID, proposed IP address, network mask, and IP address lease time.

Lease time is the amount of time for which the IP address will be valid.

It is common for the server to set the lease time to several hours or days.

The newly arriving client chooses from one or more server offers and responds with a DHCP request message.

The DHCP request message echoes back the configuration parameters.

The server responds to the DHCP request message with a DHCP ACK message.

The DHCP ACK message confirms the requested parameters.

DHCP can return more than just the allocated IP address on the subnet.

DHCP can return the address of the first-hop router for the client.

DHCP can return the name and IP address of the DNS server.

DHCP can return the network mask indicating network versus host portion of the address.

Conceptually, the Internet is divided into over 200 top-level domains.

Each domain is partitioned into subdomains which are further partitioned.

All domains can be represented by a tree where leaves represent domains with no subdomains.

The top-level domains come in two categories: generic and countries.

The original generic domains were com, edu, gov, int, mil, net, and org.

ICANN approved four new general-purpose top-level domains: biz, info, name, and pro.

Every domain can have a set of resource records associated with it.

For a single host, the most common resource record is its IP address.

The primary function of DNS is to map domain names onto resource records.

A resource record is a five-tuple presented as ASCII text with one line per resource record.

The Domain_name field tells the domain to which the record applies.

The Time_to_live field gives an indication of how stable the record is.

The Class field for Internet information is always IN.

The Type field tells what kind of record this is.

The Value field can be a number, a domain name, or an ASCII string.

An SOA record provides the name of the primary source of information about the name server's zone.

The A record holds a 32-bit IP address for some host.

Every Internet host must have at least one IP address so other machines can communicate with it.

MX records specify the name of the host prepared to accept email for the specified domain.

NS records specify name servers.

CNAME records allow aliases to be created.

PTR records are used to associate a name with an IP address for reverse lookups.

HINFO records allow people to find out what kind of machine and operating system a domain corresponds to.

TXT records allow domains to identify themselves in arbitrary ways.

A single name server could contain the entire DNS database but would be overloaded and useless.

The DNS name space is divided into nonoverlapping zones to avoid problems with a single source of information.

Normally a zone has one primary name server and one or more secondary name servers.

To improve reliability, some servers for a zone can be located outside the zone.

There are two types of DNS queries: recursive queries and iterative queries.

The type of query is determined by a bit in the DNS query.

In iterative resolution, the local DNS server forwards the query to the root DNS server.

The root DNS server finds the suffix and returns a list of IP addresses of the top level DNS server responsible for that suffix.

The local DNS server then sends the query to one of the top level DNS servers.

The top level DNS server finds the suffix and returns the IP address of the authoritative DNS server.

The local DNS server sends the query to the authoritative DNS server.

The authoritative DNS server responds with the IP address of the requested host.

The local DNS server sends the result of the resolution to the host.

The authoritative DNS is the one responsible for a domain and holds entries for that domain.

DNS responses are cached for quick response for repeated translations.

DNS negative queries are cached to avoid repeating past mistakes.

Cached data periodically times out based on the lifetime controlled by the owner of the data.

Reverse DNS is the task of given an IP address, finding its name.

Reverse DNS maintains a separate hierarchy based on IP names.

DNS is not centralized because a single point of failure, traffic volume, and distant centralized database do not scale.

LDAP stands for Lightweight Directory Access Protocol.

LDAP is a simplified version of the OSI X.500 directory service.

LDAP organizes information as a tree and allows searches on different components.

LDAP can be regarded as a white pages telephone book.

Cache poisoning attacks inject false DNS records into resolver cache.

Cache poisoning redirects users to malicious servers.

The Kaminsky attack exploits transaction ID predictability.

Man-in-the-Middle attacks intercept and modify DNS queries and responses.

DNS spoofing impersonates authoritative name servers and provides false DNS responses.

Birthday attacks exploit limited entropy in DNS transaction IDs.

Email servers use DNS to route messages and are vulnerable to security issues in DNS infrastructure.

The solution to DNS security issues is a protocol called DNSSEC.

DNSSEC adds a layer of trust on top of DNS by providing authentication.

Traditional DNS has no data integrity because DNS messages are not cryptographically protected.

Traditional DNS has no origin authentication so you cannot verify if the response came from the real authoritative server.

DNSSEC stands for DNS Security Extensions.

DNSSEC adds cryptographic signatures to DNS records.

DNSSEC ensures data integrity, authenticity of origin, and authenticated denial of existence.

DNSSEC does not provide confidentiality because DNS queries and responses remain visible.

DNSSEC does not provide availability and offers no protection against DoS attacks.

DNSSEC only secures the DNS layer and not applications.

DNSSEC adds digital signatures to DNS records using public-key cryptography.

A chain of trust is established from the internet's root zone down to specific DNS records of a domain.

When a DNS resolver receives a DNS request, it checks the associated digital signature.

If the signature is valid, the resolver can authenticate the origin of the DNS data.

DNSSEC uses public-key cryptography where each DNS zone has a Zone Signing Key and a Key Signing Key.

The Zone Signing Key signs individual records.

The Key Signing Key signs the ZSK and DNSKEY records.

The chain of trust goes from root zone to TLD to second-level domain to subdomain.

Each zone's KSK is signed by its parent zone.

Trust starts at the DNS Root Zone which is globally known.

New DNS record types in DNSSEC include RRSIG, DNSKEY, DS, and NSEC or NSEC3.

RRSIG is a cryptographic signature for a DNS record set.

DNSKEY is the public key used to verify RRSIG.

DS links a child zone to a parent zone and contains a hash of the child's KSK.

NSEC and NSEC3 provide authenticated denial of existence.

NSEC lists the next valid name in a zone.

NSEC3 prevents zone enumeration by hashing domain names.

In DNSSEC, the resolver queries for the domain and the authoritative server responds with the A record and an RRSIG.

The resolver fetches the DNSKEY to verify the RRSIG.

The DNSKEY is authenticated using a DS record from the parent zone.

This continues until the Root Zone where the chain of trust begins with a known public key.

The resolver confirms the response has not been tampered with and comes from the legitimate source.

DNSSEC is not a separate protocol but an extension of DNS so it uses the same transport protocols.

Most DNS and DNSSEC queries and responses use UDP on port 53.

DNSSEC responses are often larger because they include RRSIG, DNSKEY, and DS records.

If a response size exceeds the UDP limit, the client retries over TCP.

TCP is also used for tasks like zone transfers.

DNSSEC uses UDP by default and falls back to TCP when responses are too large.

Steps for a zone operator include generating ZSK and KSK pairs and publishing public keys in DNSKEY records.

The zone operator signs records with ZSK to produce RRSIG.

The zone operator publishes a DS record in the parent zone.

The zone operator regularly rolls keys by rotating KSK and ZSK.

Resolvers should use a validating resolver such as BIND or Unbound.

Resolvers should configure a trust anchor for the Root KSK.

Challenges of DNSSEC include complexity of key management and chain of trust maintenance.

DNSSEC has performance overhead due to larger responses from signatures.

Adoption rate is a challenge because not all domains and resolvers support DNSSEC.

DNSSEC provides no confidentiality and is still vulnerable to traffic analysis and DoS attacks.

Zone enumeration risk is mitigated using NSEC3.

DNS was built for public lookups so confidentiality was not a priority.

DNSSEC addressed forging of DNS responses by adding signatures, not encryption.

Encryption adds latency and complexity which would have been too heavy at Internet scale.

If you need confidentiality, use DNS over TLS or DNS over HTTPS.

DNS over TLS and DNS over HTTPS encrypt DNS queries and responses between client and resolver.

DNSSEC provides authenticity and integrity while DoT and DoH provide confidentiality and privacy.

The Internet Protocol is the fundamental communication protocol for relaying packets across interconnected networks.

IP functions at the Network Layer, which is Layer 3 of the OSI model.

The main purpose of IP is addressing and routing packets from a source host to a destination host.

Functions of IP include addressing, routing, encapsulation, fragmentation and reassembly, and error handling.

Addressing provides unique logical addresses to devices using IPv4 or IPv6.

Routing determines the best path for packet delivery across networks.

Encapsulation wraps data with IP headers that include source and destination addresses.

Fragmentation and reassembly splits large packets into smaller ones suitable for transmission.

Error handling uses a header checksum for minimal error detection.

IPv4 uses 32-bit addresses while IPv6 uses 128-bit addresses.

IPv4 has a variable header size of 20 to 60 bytes while IPv6 has a fixed 40-byte header.

IPv4 has optional security via IPsec while IPv6 has built-in support for IPsec.

IPv4 requires NAT due to limited addresses while IPv6 does not require NAT due to huge address space.

IPv4 supports manual or DHCP configuration while IPv6 supports auto-configuration.

IP itself does not provide any form of encryption or authentication, which makes it vulnerable.

IP Spoofing occurs when an attacker sends packets with a forged source IP address.

Eavesdropping or packet sniffing intercepts IP packets in transit to read sensitive data.

Replay attack resends captured valid packets maliciously.

Man-in-the-Middle attack intercepts and alters communication between two parties.

IPsec mitigates attacks by securing IP packets through encryption and authentication.

IPsec stands for Internet Protocol Security.

IPsec is a suite of open standards that secures IP communications by authenticating and encrypting each IP packet.

IPsec operates at the Network Layer.

IPsec works with both IPv4 and IPv6.

IPsec is used in VPNs, secure gateways, and site-to-site communications.

Objectives of IPsec include confidentiality, integrity, authentication, and anti-replay protection.

Confidentiality prevents unauthorized users from reading data through encryption.

Integrity ensures data is not altered during transmission using hashing.

Authentication verifies the identity of sender and receiver.

Anti-replay protection prevents attackers from resending old captured packets.

IPsec provides key management services including key exchange and key revocation.

IPsec is an open standard protocol supported by a wide range of vendors.

IPsec provides two primary protocols: Authentication Header and Encapsulating Security Payload.

Authentication Header provides data origin authentication and integrity.

Authentication Header does not provide encryption so data remains visible.

Authentication Header protects the IP header and payload against tampering.

A bank might use AH for verifying authenticity of status messages between internal routers.

Encapsulating Security Payload provides encryption, authentication, and integrity.

Encapsulating Security Payload protects the data payload and optionally the IP header.

Encapsulating Security Payload supports both Transport Mode and Tunnel Mode.

A bank uses ESP to encrypt all data between ATMs and its central data center.

Transport Mode encrypts only the payload while the original IP header remains intact.

Transport Mode is used for secure communication between two hosts such as ATM and bank server.

Tunnel Mode encrypts the entire IP packet and encapsulates it in a new one with a new IP header.

Tunnel Mode is used for VPNs between branch offices.

Security Associations define the relationship between two devices that agree to communicate securely.

Security Associations specify parameters like encryption algorithm, keys, and mode.

Each direction uses its own Security Association with inbound SA and outbound SA.

Internet Key Exchange manages negotiation of SAs and exchange of encryption keys.

IKE Phase 1 establishes a secure channel called the IKE SA.

IKE Phase 2 negotiates IPsec SAs for data transfer.

Common encryption algorithms include AES and 3DES.

Common authentication algorithms include HMAC-SHA-1 and HMAC-SHA-256.

Common key exchange algorithm is Diffie-Hellman.

Advantages of IPsec include secure data transfer over untrusted networks.

IPsec is transparent to applications so no app modification is needed.

IPsec can secure all IP-based traffic including TCP, UDP, and ICMP.

IPsec supports authentication and encryption simultaneously.

IPsec is essential for VPNs and secure branch interconnections.

Limitations of IPsec include configuration complexity for SA and IKE setup.

IPsec has overhead from encryption and decryption that impacts performance.

IPsec has NAT compatibility issues especially with AH.

IPsec is difficult to troubleshoot due to encrypted traffic.

In modern computer networks, secure data transmission is essential.

TCP ensures reliable communication between devices.

SSL and TLS provide encryption and authentication on top of TCP.

TCP is a connection-oriented, reliable transport layer protocol.

TCP ensures that data is delivered accurately and in order between applications over IP networks.

TCP is defined in RFC 793 and later updates.

TCP is connection-oriented and requires a three-way handshake before data transfer.

TCP uses acknowledgments and retransmissions for reliable delivery.

TCP ensures data arrives in sequence using sequence numbers.

TCP uses flow control to prevent the sender from overwhelming the receiver.

TCP uses congestion control to prevent network congestion using algorithms like AIMD.

TCP connection establishment uses a three-way handshake with SYN, SYN-ACK, and ACK.

TCP connection termination uses FIN and ACK from both sides.

TCP alone does not provide encryption or authentication.

Attackers can perform session hijacking, TCP spoofing, and SYN flooding against TCP.

SSL and TLS are layered on top of TCP to provide secure communication.

SSL was developed by Netscape in the mid-1990s.

SSL provides confidentiality, integrity, and authentication over TCP.

SSL operates between the Application Layer and the Transport Layer.

SSL has evolved into TLS but the term SSL is still widely used.

SSL consists of two main layers: the SSL Record Protocol and the SSL Handshake Protocol.

The SSL Record Protocol provides data encapsulation, compression, and encryption.

The SSL Handshake Protocol establishes session parameters, authenticates parties, and negotiates encryption keys.

An SSL client and server negotiate a stateful connection using a handshaking procedure.

The client presents a list of supported ciphersuites during the handshake.

The server picks the strongest cipher and hash function that it also supports.

The server sends its identification in the form of a digital certificate.

The client encrypts a random number with the server's public key to generate session keys.

Both parties generate key material for encryption and decryption from the random number.

SSL Handshake Phase 1 establishes security capabilities.

SSL Handshake Phase 2 handles server authentication and key exchange.

SSL Handshake Phase 3 handles client authentication and key exchange.

SSL Handshake Phase 4 completes the setting up of a secure connection.

SSL is vulnerable to attacks like POODLE and BEAST.

SSL is deprecated in favor of TLS.

TLS is the successor to SSL and is standardized by the IETF.

TLS versions include TLS 1.0, 1.1, 1.2, and 1.3.

TLS provides stronger encryption and better performance than SSL.

TLS encryption protects data from eavesdropping using symmetric encryption like AES and ChaCha20.

TLS authentication uses digital certificates like X.509 to verify identity.

TLS integrity uses HMAC to detect tampering.

TLS 1.3 provides forward secrecy which prevents past sessions from being decrypted even if keys are compromised.

TLS 1.3 has a simplified handshake of one round trip.

TLS 1.3 uses stronger cryptography and no RSA key exchange.

TLS 1.3 has default Perfect Forward Secrecy.

TLS 1.3 handshake steps include Client Hello, Server Hello, Server Finished, and Client Finished.

The TLS Record Protocol fragments application data, compresses optionally, applies MAC and encryption, and transmits over TCP.

SSL is proprietary to Netscape while TLS is an IETF standard.

SSL latest version is SSL 3.0 which is deprecated while TLS latest version is TLS 1.3.

SSL is vulnerable to known attacks while TLS has strong encryption and forward secrecy.

SSL handshake is slower while TLS handshake is faster especially in TLS 1.3.

SSL uses outdated cipher suites like RC4 and DES while TLS uses modern cipher suites like AES, ChaCha20, and SHA-256.

When visiting a secure website, the browser initiates a TCP connection to the server on port 443.

A TLS handshake occurs to establish a secure channel.

All HTTP requests and responses are encrypted through the TLS channel.

HTTPS ensures confidentiality, integrity, and authentication.

Mauritius Bank Ltd uses TCP for reliable connection and TLS 1.3 for encryption and authentication.

The bank installs an X.509 certificate from a trusted Certificate Authority.

Users connect via HTTPS ensuring no eavesdropping, verified bank identity, and integrity of data.

TLS protects against eavesdropping, MITM attacks, data tampering, and replay attacks.

TLS is used in HTTPS, SMTPS, IMAPS, FTPS, and VPNs like OpenVPN.

SSL and TLS cannot be directly used with UDP because they are built on top of TCP.

UDP is message-oriented and connectionless so the SSL/TLS handshake cannot work properly over UDP.

The correct protocol to secure UDP is DTLS.

DTLS stands for Datagram Transport Layer Security.

DTLS is defined in RFC 6347 for DTLS 1.2 and RFC 9147 for DTLS 1.3.

DTLS provides the same security guarantees as TLS including confidentiality, integrity, and authentication.

DTLS works over UDP and handles packet loss, out-of-order delivery, and duplicated datagrams.

DTLS handshake includes ClientHello, HelloVerifyRequest, ClientHello with cookie, ServerHello and Certificate, Key Exchange, and Finished.

DTLS uses a cookie exchange to prevent DoS attacks.

DTLS supports key exchange with ECDHE, encryption with AES-GCM and ChaCha20-Poly1305, integrity with HMAC-SHA256, and authentication with X.509 certificates or pre-shared keys.

Benefits of DTLS include low latency, security, compatibility with TLS infrastructure, and flexibility for real-time applications.

Limitations of DTLS include complexity of handling packet loss and reordering, extra step for cookie exchange, and handshake delay.

For file transfers or email, TLS over TCP is better than DTLS.

DTLS is used in VoIP, WebRTC, VPNs like OpenVPN, and IoT communication with CoAP.

Kerberos is a computer network authentication protocol that works on the basis of tickets.

Kerberos allows nodes communicating over a non-secure network to prove their identity to one another in a secure manner.

Kerberos protocol messages are protected against eavesdropping and replay attacks.

Kerberos builds on symmetric key cryptography and requires a trusted third party.

Kerberos may optionally use public-key cryptography during certain phases of authentication.

Kerberos uses UDP port 88 by default.

The client authenticates itself to the Authentication Server which forwards the username to a key distribution center.

The KDC issues a ticket-granting ticket which is time stamped and encrypted using the user's password.

The encrypted TGT is returned to the user's workstation.

The TGT is issued infrequently, typically at user logon.

The TGT expires at some point but may be transparently renewed by the user's session manager.

When the client needs to communicate with another node, the client sends the TGT to the ticket-granting service.

The TGS usually shares the same host as the KDC.

The TGS verifies the TGT is valid and the user is permitted to access the requested service.

The TGS issues a ticket and session keys which are returned to the client.

The client sends the ticket to the service server along with its service request.

If a TGT is stolen, it can be used to access network services.

A stolen TGT is only a problem until the ticket expires in a few hours.

Tor is an anonymity network that masks a user's IP address by routing traffic through multiple encrypted nodes.

Tor was originally developed for secure communications but now allows both legitimate privacy and anonymous Internet activity.

Tor uses onion routing where data is encrypted in layers.

Each relay node only knows the previous and next hop so no single node knows both source and destination.

Key components of Tor include guard nodes, middle nodes, exit nodes, and bridge nodes.

Guard nodes are entry points to the Tor network.

Middle nodes are intermediate hops in the Tor network.

Exit nodes are the final hop before reaching the Internet.

Bridge nodes are unlisted entry points used to avoid censorship.

Tor has legitimate uses including privacy protection, journalists communicating safely, whistleblowers, and circumventing censorship.

Malicious traffic from Tor exit nodes is disproportionately high.

Attackers use Tor because it obscures their identity and location.

Attackers use Tor because it allows switching exit nodes to evade IP-based blocking.

Attackers use Tor because it frustrates attribution and remediation efforts.

Tor use aligns with several attack stages in the MITRE ATT&CK Framework.

Tor is used for anonymous scanning of target networks during reconnaissance.

Tor is used for probing or exploiting internet-facing services during initial access.

Tor is used for malware communicating with servers during command and control.

Tor is used for sending stolen data out during data exfiltration.

Tor is used for conducting DoS attacks from anonymous exit nodes during impact.

Blocking Tor exit node addresses at gateways, firewalls, or routers is the preferred strategy where legitimate use is low.

Blocking Tor reduces anonymous reconnaissance and exploitation with minimal impact on most legitimate users.

If blocking is not feasible, security teams should monitor Tor traffic to identify suspicious patterns.

Logging connections from Tor exit nodes creates an audit trail for investigation.

Tor logs should be protected, centralized, and reviewed regularly.

Before blocking Tor, organizations should assess if important users access services through Tor.

Organizations may decide to allow specific Tor traffic but should still monitor and secure those connections.

Diffie-Hellman is a key exchange protocol that allows two parties with no prior knowledge of each other to establish a shared secret key over an insecure network.

The shared secret can then be used to encrypt subsequent communications using a faster symmetric encryption algorithm like AES.

The security of Diffie-Hellman relies on the mathematical difficulty of calculating discrete logarithms.

Diffie-Hellman is widely used in secure web communication with TLS, VPNs with IPsec, and SSH.

Diffie-Hellman lets two parties arrive at the same secret without an eavesdropper being able to figure it out.

Diffie-Hellman is a key exchange algorithm, not an encryption algorithm.

The only job of Diffie-Hellman is to create a shared secret.

Diffie-Hellman solves the problem of getting a symmetric key to both sides without anyone else seeing it.

Diffie-Hellman does not provide authentication and does not prove who you are talking to.

The security of Diffie-Hellman is based on the Discrete Logarithm Problem.

Symmetric encryption uses a single shared key for both encryption and decryption.

Symmetric encryption is very fast and efficient with AES as a perfect example.

Asymmetric encryption uses a key pair with a public key to encrypt and a private key to decrypt.

Asymmetric encryption is much slower than symmetric encryption with RSA as a common example.

Symmetric encryption is ideal for encrypting large amounts of data like in an IPsec VPN tunnel.

The challenge is how to securely get the single shared key to both devices in the first place.

Diffie-Hellman provides a way for two devices to agree upon a shared secret even if an attacker is listening.

The magic of Diffie-Hellman is that two sides exchange public information but can independently create an identical secret.

Two parties agree on public parameters, choose private secrets, exchange computed values, and independently derive the same shared key.

An attacker who sees everything exchanged cannot compute the shared secret efficiently.

In the paint analogy, Alice and Bob publicly agree on a starting color that is not secret.

Each person selects a secret color that they keep to themselves.

Alice and Bob each mix their own secret color with the shared color and publicly exchange the mixed colors.

Each of them mixes the color received from the partner with their own private color.

The result is a final color mixture that is identical to their partner's final color mixture.

A third party listening to the exchange would only know the common color and the first mixed colors.

Diffie-Hellman does not authenticate participants.

In a Man-in-the-Middle attack, Eve intercepts and replaces keys between Alice and Bob.

Eve creates two different shared keys, one with Alice and one with Bob.

Eve can decrypt, modify, and re-encrypt messages in a MITM attack.

The solution to MITM is to use authentication with digital signatures, certificates, or authenticated DH.

Ephemeral Diffie-Hellman uses temporary keys and provides Perfect Forward Secrecy.

Elliptic Curve Diffie-Hellman uses elliptic curves instead of modular arithmetic.

Elliptic Curve Diffie-Hellman is more efficient and secure with smaller keys.

Perfect Forward Secrecy ensures that even if long-term private keys are compromised, past session keys remain secure.

Systems with Perfect Forward Secrecy generate a unique session key for every session.

Temporary keys generated for each session ensure that if one key is compromised, it does not compromise other communications.

Long-term keys used for authentication do not compromise other communication if they are compromised.

Perfect Forward Secrecy adds a layer of security where long-term keys might be at risk.

Advantages of Diffie-Hellman include secure key exchange over an insecure channel.

Advantages of Diffie-Hellman include no prior shared secret required and scalability for internet use.

Limitations of Diffie-Hellman include vulnerability to MITM attacks without authentication.

Limitations of Diffie-Hellman include being computationally expensive with large primes.

Limitations of Diffie-Hellman include requiring proper parameter selection.
